## 1. Продукт: назначение и объекты

Система помогает редакции разбирать региональные инфоповоды и обращения, хранить проверенные сведения, анализировать открытые обсуждения, готовить фактические разъяснения. Состоит из:

1. **Веб-студии:** настройка и управление всеми сущностями.
2. **ИИ-ядра:** анализ материалов, проверки, интервью, исследование, предложения изменений, навыки.
3. **MAX-бота:** ежедневная работа сотрудников с задачами через общий backend.

Не смешивать:
- **Личность** — устойчивый вымышленный аналитический паспорт; имеет версии.
- **Тема** — версионируемое досье события с проверенными/спорными утверждениями.
- **Источник** — документ/URL/сообщение с происхождением и временем.
- **Знание / утверждение (claim)** — отдельное фактическое суждение, привязанное к источникам.
- **Задание** — конкретный анализ одного или множества материалов, с зафиксированными версиями зависимостей.
- **ИИ-навык** — версионируемая инструкция + схема входа/выхода + тесты.

## 2. Дизайн-система: NestJS-inspired, но уникальная

Основной референс — актуальный сайт NestJS; использовать его атмосферу, **не копируя логотип, фирменные иллюстрации и узнаваемые композиции пиксель-в-пиксель**.

### Палитра / токены
- Canvas: `#050303`.
- Поверхность панели: `#0B0B0B`.
- Приподнятая поверхность: `#181818`.
- Линии: `#1E1C1C`, более заметная граница `#373535`.
- Основной текст: `#FFFFFF` / мягкий `#F5F2F2`.
- Второстепенный текст: `#9B9A9A` (при необходимости осветлять ради контрастности).
- Акцент: crimson `#EA2845`.
- Подсветка/градиенты: garnet `#780F20` → `#050303`.
- Семантические цвета успеха/предупреждения/ошибки — отдельные токены, не красить все статусы малиновым.
- CSS custom properties, никакой россыпи случайных hex-кодов по компонентам.

### Шрифты и графика
- Заголовки и основной UI: **Manrope**; микронадписи, версии, даты и тех. статусы: **Geist Mono**. Поддержать кириллицу и корректную загрузку/fallback.
- Иконки: Lucide; единый размерный ряд и толщина линий.
- Скругления 12–20px в рабочем UI, большие радиусы только у hero/крупных блоков.
- Мягкие border 1px, минимум тяжёлых теней и чрезмерного glassmorphism.

### Движущийся фон
- На фоне главного экрана — **непрерывное, но очень плавное** малиново-гранатовое свечение, медленно перемещающиеся размытые световые пятна, редкое мерцание точек и крайне деликатная текстура.
- CSS gradients + transform/opacity или оптимизированный Canvas; не тяжёлое WebGL по умолчанию.
- Фон отдельным фиксированным слоем, `pointer-events: none`, контент с гарантированной читаемостью.
- На формах, таблицах и редакторе — заметно менее интенсивный фон.
- `prefers-reduced-motion`: полностью статичный фон; при скрытой вкладке избегать затратных анимаций.
- Плавные hover, смена вкладок, drawer/modal, skeleton/loading, появление предложений ИИ; анимации ориентировочно 150–300 мс, без отвлекающих бесконечных переходов UI.
- Не использовать тяжёлый video background, бесконтрольные частицы или анимации, создающие лаги.

### Навигация
**Закреплённая верхняя панель (sticky/fixed), БЕЗ постоянного левого глобального сайдбара.**

Слева: оригинальный знак проекта + «ЛИЧНОСТИ».  
Центр: **Обзор · Личности · Контекст · Задания · Лаборатория**.  
Справа: глобальный поиск, уведомления, аватар/меню пользователя, настройки в меню.

На мобильных — компактная верхняя шапка и раскрываемое меню; на планшете аккуратное схлопывание пунктов. Панель может иметь эффект дымчатого стекла с blur, но подложка достаточно плотная для контраста. Активный пункт — тонкий индикатор/подсветка.

**Контекст** имеет локальные вкладки: Темы / База знаний / Источники / Мониторинг.  
**Личности**: Каталог / Ожидают проверки / Архив.  
**Лаборатория**: Тесты персон / ИИ-навыки / Диагностика.  
Из глобального меню доступны Сотрудники, Права, API/модели, MAX, Аудит, Общие настройки.

Общее расположение: max-width примерно 1440–1600px, адаптивная сетка, плотный продуктивный интерфейс. На главной допускается выразительный hero, на рабочих страницах — функциональные заголовки без огромных пустых областей.

### `/` или `/overview` — Обзор

- Данные исключительно из API; если БД пуста — продуманные empty states, без нарисованной статистики.

### `/personas` — Каталог
- Поиск, сортировка, фильтры по статусам, карточки/таблица с переключателем представления.
- На карточке: аватар/инициалы, имя, краткий контекст, версия, статус, автор, дата, число замечаний.
- Создание вручную или с ИИ, архивирование, открытие паспорта; массовые действия только безопасные.
- Предусмотреть импорт исходной **семёрки как черновиков** отдельным seed-скриптом с флагом (не активировать автоматически): Артем Вишнев, Любовь Богданова, Галина Воронова, Андрей Бочаров, Валентина Абрамова, Игорь Давыдов, Вадим Мельников. Основываться на кратких ранее согласованных легендах; неизвестные детали оставлять неизвестными, не выдумывать как факты.

### `/personas/:id` — Рабочая карточка личности
Трёхколоночная рабочая композиция на больших экранах:
- Слева **локальная навигация** по девяти разделам паспорта, счётчики заполненности и замечаний (это не глобальный сайдбар).
- В центре структурированные поля + подробное повествовательное описание выбранного раздела, версия, ручное редактирование.
- Справа **ИИ-ассистент**: интервью, обнаруженные противоречия, предложения, сравнение «было/предлагается», действия принять/исправить/отклонить.
- На узких экранах локальная навигация и ИИ-панель превращаются во вкладки/drawer.
- Вверху карточки: имя, видимый статус, версия, «Проверить», «Лаборатория», «Отправить на согласование», «Активировать» (по правам/состоянию).
- Вкладки: Паспорт / Интервью / Предложения / Тесты / Версии и история.

**Девять разделов паспорта:** 1) базовая легенда и биография; 2) семья и окружение; 3) жизненный опыт; 4) характер; 5) мировосприятие и логика рассуждений; 6) компетенции и границы знаний; 7) речевой почерк; 8) поведенческие реакции и неопределённость; 9) ограничения, источники и неизвестное. Структура JSON-schema-версионируемая, не монолитная HTML-строка.

Для каждого значения хранить: `value`, `source_kind` (`original_legend`, `editor`, `ai_suggestion`), `certainty` (`defined`, `hypothesis`, `unknown`), редакторское подтверждение и ссылки на зависимые поля. Гипотетические детали не становятся автоматически установленными.

**ИИ-интервью:** адаптивные раунды по 3–5 вопросов, редактор может пропустить/завершить, ответы фиксируются; ИИ формирует только *предложения*. Никаких автоматических перезаписей паспорта. Предложение имеет diff, причину, затрагиваемые поля, статус pending/accepted/rejected/stale, автора/время/версию. Редактор может отредактировать предложение перед принятием.

**Проверка согласованности:** после существенной правки — проверка всего паспорта с выборочной фиксацией найденных зависимостей. Разделять настоящие противоречия, неуточнённость и необычные, но совместимые качества. При изменении версии все старые предложения и проверки должны корректно инвалидироваться по `content_hash`.

**Лаборатория личности:** 6 групп испытаний: биографическая согласованность, характер, границы компетенций, восприятие ситуаций, устойчивость языка, работа с неизвестным. Стандартный набор тестовых случаев + повторные прогоны + сравнительная проверка версий. Вывод по каждому тесту: pass/warning/critical, объяснение, контекст и замечания. Не заменять рубрику фиктивным процентом качества.

**Активация:** только редактор или руководитель; редактор **может утверждать собственный паспорт**. Все критические замечания должны быть исправлены до активации. Некритические допускаются. Утверждённая версия immutable; следующий цикл создаёт новый draft. Активная версия продолжает работать до замены/приостановки. Аудит решений обязателен.

### `/context/topics` и `/context/topics/:id` — Темы
- Каталог, поиск, статусы, фильтры, география, категории.
- Гибридное создание: человек вручную ИЛИ ИИ предлагает новый черновик из задания, если не найдена соответствующая тема; человек подтверждает создание.
- Досье: суть, география/сроки, предыстория, участники, подтверждённые факты, неизвестное, противоречия, вопросы жителей, источники, даты актуальности, обновления и версии.
- «Карточка понимания»: `summary`, `facts`, `open_questions`, `conflicts`, `gaps`, `understood`, `understood_reason`, `sources`. Понимание темы НЕ означает подтверждения каждого факта.
- ИИ-проверка → редакторское утверждение → активное досье. Редактор может утвердить собственную тему.
- Существенные изменения создают новую версию; сохранённые задания ссылаются на использованную версию.

### `/context/knowledge` — База знаний
- Три уровня: глобальные материалы; материалы темы; документы задания.
- Загрузка TXT, MD, PDF, DOCX, CSV, XLSX, PNG/JPG/WEBP и URL; проверка MIME/размера, извлечение текста, статусы ошибок.
- Тексты документов и утверждения с источниками, фильтрами и поиском.
- Поиск полнотекстовый + pgvector как опциональное улучшение, но обязательно точное указание источника и excerpt.
- Новые материалы не становятся утверждёнными фактами без проверки.

### `/context/sources` — Реестр источников
- URL/имя, тип (веб, API, RSS, файл, публичное обсуждение), район/география, тематика, способ подключения, частота опроса, разрешённые способы доступа, статус, дата последней проверки, ошибки.
- Добавление, редактирование, отключение, проверка соединения, история импортов.
- Белые списки приоритетных ресурсов + дополнительный открытый веб-поиск. Не обходить закрытый доступ, капчи и ограничения платформ.
- Проверка SSRF, запрет внутренних IP/локальных адресов при загрузке URL.

### `/context/monitoring` — Мониторинг
- Автомониторинг **только выбранных редактором важных тем**, выключен по умолчанию.
- Частоты: каждые 4 часа / ежедневно / еженедельно; ограничение запросов и бюджет.
- Два контура: (а) новости/факты/даты/документы и (б) доступные публичные вопросы и жалобы.
- Сбор: заданные источники + поиск по теме в открытом интернете, только когда доступен реальный поисковый провайдер; отсутствие провайдера показывать в UI.
- Дедупликация по URL и хэшу, сравнение утверждений, поиск расхождений, обнаружение новых вопросов, очередь предложений для редактора.
- Важное изменение — уведомление; обычные — дайджест. Критический конфликт временно помечает *конкретное утверждение* как небезопасное для использования до проверки; всё досье необязательно блокируется.
- Мониторинг не меняет утверждённую версию автоматически. Хранить run history, ошибки, время, стоимость и обнаруженные изменения.
- Анализ обсуждений показывать только как анализ собранной нерепрезентативной выборки; не делать выводов обо всех жителях и не выделять индивидуальные политические профили.

### `/tasks` и `/tasks/:id` — Задания
- Новое задание: вставить текст, ссылку, один/несколько файлов; поддержка разных форматов в одном запросе.
- Быстрый режим для одного обращения / пакетный для множества комментариев.
- Два входа: сначала тема/аналитическая персона, потом материал; или сначала материал, потом предложенная тема/аналитическая перспектива с выбором сотрудника.
- Результат: суть вопроса, подтверждённые сведения и ссылки, спорное/неизвестное, группировка проблем, проект **прозрачно авторизованного** информационного разъяснения, предложения дальнейших действий.
- Задание закрепляет id и версии тем/паспортов/навыков/модели, логи, состояние queued/running/review/completed/failed. Возможность повторного прогона и обратной связи.

### `/lab` — Лаборатория

- Реестр навыков, редактор инструкции и JSON-схем входа/выхода, тестовый запуск, история версий, активация новых версий.

### `/settings` — Система

- Рабочий UI на русском, доступность клавиатурой, понятные ошибки, подтверждение опасных действий.

## 4. Роли и правила доступа

- `admin`: инфраструктура, аккаунты, конфигурация; активация контента только при наличии отдельной роли редактора.
- `editor`: редактирует/проверяет/утверждает паспорта и темы, включая созданные им самим; настраивает источники и мониторинг.
- `author`: создаёт и редактирует черновики, запускает интервью/проверки, не активирует.
- `operator`: задачи и использование утверждённых сущностей через MAX/веб, без публикации справочника.
- Роли можно совмещать. Проверять права на backend, а не только скрывать кнопки.
- Все действия `create/edit/accept/reject/approve/activate/suspend` — audit trail со временем, субъектом, сущностью и версией.

**Миграции обязательны.** Каждая активная версия имеет immutable-снимок, `content_hash` и метаданные утверждения; источники и отчёты тестов ссылаются на точные версии. Не хранить API-ключи в открытых полях БД и не отправлять их на frontend.

## 6. Backend / API / ИИ

### Стек
- Frontend: React + TypeScript + Vite; React Router, TanStack Query, Tailwind CSS и качественные доступные UI-примитивы (например, Radix/shadcn), Motion для анимаций. Формы — валидируемые, компоненты переиспользуемые.
- Backend: Python + FastAPI + Pydantic v2 + SQLAlchemy + Alembic.
- PostgreSQL + JSONB; `pgvector` только с корректными миграциями и graceful fallback на полнотекстовый поиск.
- Redis + Celery (или одна чётко обоснованная альтернатива) для фоновых заданий и расписания; без дублирования задач, с идемпотентностью.
- Файлы: локальный storage для разработки и адаптер для S3-compatible в production.
- Docker Compose для локального запуска frontend/backend/postgres/redis/worker; `.env.example`; отдельные health/ready endpoints.
- Тесты: pytest для backend, Vitest/RTL для UI, Playwright для сквозных сценариев.

### API, минимальные ресурсы
`/api/v1/auth`, `/users`, `/personas`, `/personas/{id}/versions`, `/personas/{id}/interviews`, `/personas/{id}/proposals`, `/personas/{id}/validations`, `/personas/{id}/tests`, `/personas/{id}/activate`, `/topics`, `/topics/{id}/versions`, `/knowledge`, `/sources`, `/monitoring`, `/tasks`, `/skills`, `/notifications`, `/audit`, `/integrations/max`.

Сделай OpenAPI, единообразные DTO/ошибки, pagination/filtering, ограничения, RBAC, логирование с request id. У больших операций — job id + polling/обновление статусов (SSE/WebSocket лишь по необходимости).

### ИИ-интеграция
Адаптер OpenAI-compatible API с конфигурацией `base_url`, `model`, таймаутов/лимитов и ключа только на сервере. Возможность подменить провайдера, не переписывая бизнес-логику.

Версионируемые навыки: `source-reader`, `topic-researcher`, `fact-checker`, `discussion-analyzer`, `knowledge-manager`, `persona-analyst` (только внутреннее моделирование), `plain-language-editor` (прозрачный автор), `quality-controller`.

Каждый навык: system instruction, input/output Pydantic/JSON Schema, версия, тестовые случаи, строгая проверка результата, retries, trace, стоимость. Внешние данные считать недоверенными, защищаться от prompt injection. Не превращать гипотезы в факты. Для поиска в интернете нужен реальный подключаемый search provider; не утверждать, что модель «проверила интернет», если доступ отсутствует.

## 7. MAX-бот

- Один backend — источник истины; бот не содержит дублирующихся знаний и паспортов.
- Авторизация сотрудника и привязка MAX user id через разовый код/проверенный механизм, админ подтверждает права.
- Меню: «Новое задание», «Мои задания», «Темы», «Помощь»; два режима — отдельный материал и пакетный анализ.
- Поддержка текста, доступных вложений и ссылок; прогресс, обработка ошибок, повтор/отмена, история, возврат к результату.
- На запрос по устаревшему факту — предупреждение и исключение спорных утверждений из подтверждённого ответа.
- Не давать боту инструментов управления скрытыми независимыми аккаунтами и автоматической публикации в публичные дискуссии.
- Для актуального MAX API использовать документацию https://dev.max.ru/docs-api, домен `platform-api2.max.ru`, заголовок `Authorization`; проверять на момент реализации изменения методов и webhook/polling.
- Если нет токена — реализовать адаптер, типы, локальные тесты и понятный статус «MAX не подключён», не выдавать макет переписки за интеграцию.

## 8. Безопасность и качество

- Сессии/авторизация с безопасным хранением, Argon2 для паролей, HttpOnly/Secure/SameSite cookies или обоснованный эквивалент; CSRF/Rate limiting для чувствительных операций.
- RBAC в API, аудит, секреты только в env/secret storage, запрещён их вывод в логи/браузер.
- URL ingestion: SSRF protection, таймауты, лимиты размера, блокировка локальных сетей, MIME проверка файлов, защита от zip bombs.
- Для документов: PII minimization, ограничение хранения, безопасное удаление, обработка недоверенных инструкций.
- Accessibility: доступность с клавиатуры, `aria-label`, фокус, контраст текста, reduced motion.
- UI состояния: empty/loading/error/success; надёжные сохранение черновика, подтверждение перед потерей правок, защита от гонок версий (optimistic locking/version check).
- Не делать фальшивых метрик, демонстрационных статусов или «AI approved» без реального расчёта.

## 11. Definition of Done / приёмочные сценарии

**Дизайн:** визуально очевидная отсылка к атмосфере NestJS: soot-black, crimson glow, мерцание, pinned top nav; высокое качество UI на desktop, tablet, mobile, reduced motion; без копирования чужого брендинга.

**Сценарии:**
1. Войти редактором → создать личность → сохранить структурированные поля и нарратив → обновить браузер → данные на месте.
2. Создать AI-предложение (при настроенном LLM) → принять/отклонить → в БД и истории отражено решение; AI не правит паспорт напрямую.
3. Изменить существенное поле → запустить полную проверку зависимостей → получить диагностический отчёт.
4. Имитировать/выявить критическую ошибку → API блокирует активацию даже при вызове напрямую; устранить → повторно проверить → редактор активирует.
5. Утвердить v1.0 → создать черновик v1.1 → убедиться, что v1.0 неизменна и доступна до замены.
6. Загрузить документы в тему → получить карточку понимания → утвердить тему → поиск возвращает конкретные источники.
7. Включить мониторинг для одной темы → выполнить ручной тестовый запуск → сохранить findings → показать предложения редактору; остальные темы не мониторятся.
8. Открыть задание по одному материалу и пакетному набору → получить обработанный результат/корректное сообщение об отключённом провайдере.
9. Оператор не может утвердить паспорт или тему через API; администратор без роли редактора тоже не может активировать содержимое.
10. MAX с подключённым токеном работает через общий API; без токена — явно отображается как не подключённый.

**Техника:** миграции воспроизводимы на чистой БД, Docker Compose запускается по README, health/ready работают, lint/typecheck/build/tests проходят, нет опубликованных секретов, ошибки видимы, системные логи не содержат личных данных без необходимости.
