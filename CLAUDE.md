# Claude Code — обязательный контекст проекта «Личности»

Этот репозиторий содержит внутреннюю интеллектуальную веб-платформу «Личности», общее API/БД/worker и MAX-бота. Продуктовые решения уже приняты в длительной сессии проектирования; не нужно изобретать их заново.

## ЧТО ПРОЧИТАТЬ ДО НАЧАЛА РАБОТЫ

1. **`docs/PROJECT_CONTEXT.md` — ОБЯЗАТЕЛЬНО ПРОЧИТАТЬ ПОЛНОСТЬЮ.** Это память проекта: миссия, утверждённые решения D-01–D-33, мотивы, сценарии, граничные случаи, принятый UI/UX.
2. **`LICHNOSTI_Claude_Code_TZ.md` — ОБЯЗАТЕЛЬНО ПРОЧИТАТЬ ПОЛНОСТЬЮ.** Это инженерная спецификация: маршруты, таблицы, API, стек, итерации, DoD.
3. `docs/DECISIONS.md` — решения и допущения, принятые в ходе реализации.
4. При необходимости свериться с `bassixs/asses` только по архитектурному принципу: каталог → AI understanding → редакторская проверка → активация. Не переносить сущности ассессмента напрямую.

**Если текст слишком длинный для одного запроса, читай файлы частями до конца, а не только первые строки или оглавление.** После чтения кратко сформулируй понимание доменных границ и приступай к реализации.

## НЕИЗМЕННЫЕ ПРАВИЛА ПРОДУКТА

- Веб-сайт управляет паспортами, темами, источниками, знаниями, навыками, доступами, версиями. MAX выполняет задания сотрудников; источник истины — общий backend.
- Личность = **вымышленная внутренняя аналитическая персона**, а не реальная учётная запись человека. Не строить сценарии публикации политических/общественных сообщений от имени придуманных независимых жителей и управление подставными аккаунтами. Информационные ответы имеют прозрачное авторство.
- Паспорт **гибридный**: структурированные данные + развёрнутые описания + происхождение/степень определённости. Неизвестное не выдумывать как факт.
- ИИ даёт **предложения**, не изменяет паспорт молча. Редактор принимает, редактирует или отклоняет. Интервью 3–5 вопросов за раунд с возможностью пропуска.
- Существенная правка инициирует проверку **всего паспорта**. Перед активацией — лаборатория из шести групп тестов.
- **Critical issue блокирует активацию**, warning — нет. Редактор/руководитель активирует; редактор **может утверждать собственную работу**. Активная версия immutable.
- Тема создаётся вручную или ИИ предлагает черновик из задания. Понимание ИИ не равно проверке достоверности. Изменения существенных фактов утверждает редактор.
- Мониторинг включён **только для выбранных редактором тем**, охватывает факты и доступные публичные вопросы; сбор из заданных источников + реальный веб-поиск при наличии подключения.
- Два MAX-режима: один материал и пакетный анализ; два входа: выбор контекста до материала или предложение контекста после материала. Версии должны фиксироваться в задачах.
- UI: **светлая «бумага» и чернила, оранжевый сигнальный акцент, заголовки Unbounded, портреты персонажей** — единый стиль с отчётом `/about` (решение владельца E-021 от 2026-11-17, заменяет прежнюю атмосферу NestJS). **Верхняя фиксированная навигация** (плавающая панель), без постоянного глобального левого sidebar. Трёхколоночный редактор — локальная компоновка.

## ИНЖЕНЕРНЫЙ ПРОЦЕСС

1. Проверь текущее состояние репозитория; бережно относись к имеющемуся коду/изменениям пользователя.
2. Запускай разработку **вертикальными срезами**: миграция → API с RBAC → UI → тест → документация. Не ограничивайся статичными макетами.
3. Для первых задач приоритет: локальный запуск + авторизация + каталог персон + запись/чтение PostgreSQL + базовый редактор + дизайн-система.
4. Все вызовы внешних LLM/search/MAX — через адаптеры и конфигурацию. Без ключей — честный статус «не подключено»; не показывать выдуманные результаты.
5. Нельзя утверждать прохождение тестов, запуск приложения или интеграцию, если не выполнена реальная проверка.
6. Бизнес-правила проверять **на backend**, не только в UI. Активные снимки immutable, статус проверок привязан к конкретному content hash.
7. Любые решения, не описанные как утверждённые, фиксировать в `docs/DECISIONS.md` с датой и причиной; различай `принято владельцем` и `инженерное допущение`.
8. После каждой итерации сообщай: что реально реализовано, что протестировано, как запустить, что требует ключей/доступов, что осталось.
